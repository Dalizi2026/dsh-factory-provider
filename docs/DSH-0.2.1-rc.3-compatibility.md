# DSH 0.2.1-rc.3 适配与 PR 审查

日期：2026-10-25。适配工作基于插件 1.3.9，随 1.4.0 发布；不修改 dispatch。

## 修了什么，为什么修

在隔离的官方 rc.3 Web 页面中复现了一个实际问题：修改压缩阈值后，页面提示已保存，但连接状态随后变为 `failed — HMR transactions cannot be nested`。配置文件中的数值已保存，后续模型目录同步却失败。

原因不是等待时间不够。DSH 的 HMR 服务通过 `AsyncLocalStorage` 标识当前事务；保存时发出的通知、通知创建的定时器，以及后续重试都会继承这个标记。即使原事务已经结束，重试仍会被当作嵌套事务拒绝。此前只模拟短暂忙碌状态的测试，没有覆盖真实的异步上下文传播。

本次在 Factory 模型目录同步和卸载清理前，退出旧的 HMR 上下文标记，再由 `SettingsForms → ConfigEditor → HMR.runExclusive` 正常排队保存。没有直接改宿主配置文件，也没有关闭事务检查、绕过版本校验或修改 DSH 安装包。

实现使用能力检测访问当前 HMR 的 `executing` 边界；这是经过 rc.2 / rc.3 实际验证的内部接入点，并非永久稳定的公开 API。没有这项能力的旧宿主仍走原有路径；未来 DSH 更新后仍需跑完整宿主测试，不能只凭接口名称判断兼容。

没有修改模型倍率、上下文预算、默认压缩阈值、缓存策略、上游顺序或子代理模型选择逻辑。测试使用临时账号目录、临时统计日志和临时 profile；用户的 key、账号选择和历史数据未被改动。

## PR #2：悬浮窗越界与双圆环

[PR #2](https://github.com/Dalizi2026/dsh-factory-provider/pull/2)，作者 huangzhenhao90，审查时为 open，提交 `b65f4b3`，修改 `lib/client.js`。

**越界反馈成立。** 当前保存的是绝对屏幕坐标，只在拖动过程中限制位置。换到较小屏幕、缩小窗口或恢复旧坐标后，悬浮窗可能出现在可视区域之外。

PR 增加初始化和 resize 时的位置约束，方向合理，但用固定的 220×100 估算窗口尺寸。展开后的卡片高度更大，折叠后又更小，仍不足以保证整个窗口可见。建议后续单独修复时按真实元素尺寸约束，并覆盖展开/折叠、窗口变化、小视口和无效旧坐标。

双圆环属于另一项界面设计建议，不能与越界修复混作同一个必要改动。本轮不移植位置修复，也不更换圆环设计，保留该 PR 待后续决定。

## PR #3：Gemini 接入

[PR #3](https://github.com/Dalizi2026/dsh-factory-provider/pull/3)，作者 huangzhenhao90，审查时为 open，提交 `589b622`，基于旧版 1.3.6，修改 12 个文件。

**不建议整体合并。** 当前插件自 1.3.7 起已有独立 `factory-google` 接入和原生流转换；PR 使用 DSH 内置的 `google` 名称，可能覆盖用户自行设置的 Google 配置。它还包含旧目录数量假设、不同的网关协议接法和凭据占位配置，不能直接覆盖现有实现。

其中签名内容保持、上游错误透传和禁用后不发送请求等测试方向有价值。本次据此为现有实现编写了针对性回归，补充同名 Google 配置不被替换、签名文字不改写、客户端凭据不透传、请求模型由路由固定、403/503 不额外重试和禁用后不发送等检查。

测试文件与 README 已注明建议来源和作者；没有将整个 PR 的实现记为已合并。两项 PR 均未评论、合并或关闭；本次发布依据用户明确授权进行。
